# Changelog

All notable changes to Bearings are documented in this file.

# 0.5.0

Two request smuggling fixes, found by checking Bearings against the CVEs of the last five years.

- **A bare LF in the trailer section of a chunked request body is refused.** Before, after `0` CRLF LF, or after a trailer line that ended with LF, the decoder read on to the next CRLF CRLF while the trailer parser stopped at the LF, so the bytes in between were dropped without an error. Behind a proxy that ends the body at the bare LF (RFC 9112 2.2 lets a recipient take a bare LF as a line end), the next request on the connection was swallowed and the proxy's responses were matched to the wrong requests (the class of CVE-2025-43859). The decoder now fails the body with `deTrailerBareLf` ("bare LF in the trailer section"), and the connection closes after the response. hyper behaves as Bearings did before.
- **An HTTP/1.1 request without `Host`, or any request with two `Host` lines, gets 400** (RFC 9112 3.2). With two lines, the server and a proxy could each use a different one. The handler is not called. HTTP/1.0 requests may still omit `Host`. The new parse error is `h1peHeaderHost` ("missing or duplicate Host"). Clients that send HTTP/1.1 without `Host` (hand-written test scripts, some health checks) must add it.

- **C API: `bearings_config` starts with `size`, and the program sets it to `sizeof(bearings_config)`.** Until now every new option changed the struct's layout, so a program built against the older header had to be rebuilt (0.4.0 and 0.4.1 both did that). `bearings_server_new` now reads `size` bytes: a program built against an older header gives a smaller size and the fields it does not have take their defaults; a program built against a newer header than the library is accepted when the fields the library does not have are zero, and refused otherwise. From this version on, fields are only added at the end. A `size` of 0 or below the 0.5.0 layout (152 bytes) fails with `config.size must be sizeof(bearings_config)`. Programs built against the 0.4.1 header must be rebuilt, once more, and must set `size`: `bearings_config cfg = { .size = sizeof cfg };`. pybearings sets it.
- **A server stop between the hand-off of an upgraded socket and its delivery no longer leaks the WebSocket.** The dispatcher hands the socket to a `TUpgraded` and queues a task that gives it to the upgrade handler. When the stop reached the loop in between (the stop message is read after the socket events of an iteration and before its queued tasks), the stop closed the stream, and the handler then got the closed stream: `AcceptWebSocket`'s handler built a `TWebSocket` on it that nothing finished, so the object and the application's handler were never freed, `OnOpen` and `OnClose` never ran, and its ping and idle timers stayed armed on a loop that was still draining its other connections. The stream now has a listener of its own until it is delivered (`TUndelivered`); a stop tells the delivery, and the handler gets `UpgradeFailed('upgrade not completed')` instead of the stream. The client sees the 101 and then the connection close. Found by the first run of the unit suites on ARM64 hardware, where heaptrc reported the two blocks; the cause does not depend on the CPU, and `test_ws_echo` now has a test that stops the server at that point on any machine.
- **`, chunked` is appended to the `transfer-encoding` line only.** When the application's Transfer-Encoding did not end in `chunked` (`transfer-encoding: gzip`), the encoder appended `, chunked` to it, as it must, and then also to the next joined header line of the response (`connection: close, chunked`, `trailer: x-sum, chunked`): the mark was never cleared. Inherited from hyper, where the same happens. The lines after the Transfer-Encoding are now written as given.
- **A listener paused by the connection limit resumes as soon as a slot is free.** The listener takes a slot of `MaxConnections` before each `accept4` and gives it back when the count was over the cap or there was nothing to accept. The give-back was a plain decrement: it resumed no listener, and a connection closing on another loop at that moment saw the count still raised by the unused slot and resumed none either, so a paused listener stayed out of epoll until the 1 s fallback timer. The give-back now goes through the same release path as a closing connection (`TListener.OnSlotBack`). Seen as `test_server_ops` `Four_loops_resume_their_listeners` failing under load.
- **One test runner: pytest.** `pytest.ini` and `tests/*.py` build and run every test of the repository: the fpcunit suites (every test method a pytest subtest; `--fpc-suite=Class[.Method]` narrows a run), the heaptrc runs, the expected-value tests (`UPDATE=1` as before), the split fuzz, the hot-path assembler check, the version check, the drd and memcheck runs, the worker stress, the wire conformance gate (inline and worker executor, every case a subtest) and the pybearings tests. The tiers are the marks `fast` and `full` (`make test`, `make test-full`); `-k`, `-m`, `--lf` and `-n` (pytest-xdist) select and parallelize as usual. `tests/unit/run_all.sh`, `tests/unit/test_golden.sh`, `tests/conformance.sh`, `conformance/pascal-server/gate.sh` and `gate_worker.sh` are gone; `TARGET=aarch64` and the environment variables they took (`OUT_DIR`, `FPC`, `RUN`, `FUZZ_SEEDS`, `RUNS`, `JOBS`, `LOOPS`, `PROFILE`, `VALGRIND`, ...) work the same way with pytest.
- **The conformance runner and the dumb server are Python programs** (`conformance/runner/crun`, `conformance/dumb-server/dumbserver.py`; standard library only, Python 3.14), run as `python3 conformance/runner/crun run --server ... conformance/cases/h1`; nothing is built for them. The Pascal runner written earlier on 2026-11-04 was checked case by case against them before it was removed: the same outcome and, for failing cases, the same failing step, in every configuration (inline, worker executor, four loops, the dumb server with and without events), except `chunk2::pipeline_enabled` under the worker executor, which depends on the timing of one read and may pass or fail with either runner (`conformance/pascal-server/worker-exceptions.txt`). A `\u0000` escape in a case file is now a NUL byte (SPEC.md section 2).
- **The error texts are written for Bearings.** The texts of `DecodeErrorMessage`, `H1ParseErrorDescription`, `ErrorDescription` (the `detail` of a `conn_close` event, the `message` of a `request_body_error` event, Python's `BodyError`) were the texts of hyper and httparse (`Invalid chunk size line: Invalid Size`, `invalid HTTP version parsed`, `error from user's Service`, ...). They now say what happened in the terms of RFC 9112 (`invalid byte after the chunk size`, `invalid HTTP version`, `handler failed`, ...). conformance/SPEC.md 7.1 lists the body-decoder texts. Programs that match on the texts must be updated; the error kinds and `TDecodeError` values are unchanged.
- **Comments and test names no longer explain Bearings by comparison with hyper.** The source comments that justified a rule by what hyper does say the reason instead; `docs/design/deviations.md` gives every entry's reason in its own terms; the test classes `TTestConnRs`, `TTestIoRs`, `TTestDispatchHyper`, `TTestHttparseLib`, `TTestHttparseLibReq`, `TTestHttparseUri`, `TTestHttparseSimd`, `TTestChanRs` and `TTestIncomingRs` are `TTestConnReadWrite`, `TTestIoBuffers`, `TTestDispatchRegressions`, `TTestParserCore`, `TTestParserRequests`, `TTestParserUri`, `TTestParserByteClasses`, `TTestChan` and `TTestIncoming` (`--fpc-suite` takes the new names); the test methods `Hyper_defaults`, `Tick_rounding_matches_tokio`, `Level_for_matches_tokio_tests`, `Slot_for_matches_tokio_tests`, `Extra_header_limit_hyper_default` and `Extra_hyper_token_error_mapping` are `Conformance_defaults`, `Tick_rounding`, `Level_for_table`, `Slot_for_table`, `Extra_header_limit_default` and `Extra_token_error_mapping`; the comments that pointed at lines of hyper's sources (`conn.rs:1342-1355`) are gone; and the test file headers describe what the tests check (the origin of a ported test is still named).
- **`THyperError` is `TH1Error`**, `THyperErrorKind` is `TH1ErrorKind` (`h1eParse`, `h1eUser`, ... instead of `hekParse`, `hekUser`, ...) and `THyperUserKind` is `TH1UserKind` (`h1uBody`, ... instead of `hukBody`, ...). The error record of the HTTP/1 layer was named after the library Bearings was ported from. Programs that name the types (a `TConnObserver`, a body reader that looks at `PollNext`'s error) must be updated.
- **The default `MaxBufSize` is 416 KiB** (425 984 bytes). It was 417 792, the number hyper gets from 8192 + 4096 × 100; a request head may be 8 KiB longer than before.
- **`HalfClose`, `TitleCaseHeaders` and `TResponseHead.CaseMap` are gone.** The three came from hyper's builder (`half_close`, `title_case_headers`) and its `HeaderCaseMap`; no program set them (`CaseMap` could not even be reached through `TExchange`), and the only cases that did were ported hyper tests, which are gone (`http1_allow_half_close` and the extra case `half_close_response_after_fin`). The client's EOF while a request is in progress always ends the connection as `incomplete`; response header names are always lowercase (`TEncoder.EncodeTrailers` lost its title-case parameter).
- **The parser has no leniency options.** `TParserConfig` (seven switches copied from httparse, four of them for responses, which a server never parses) and `TH1Config.Parser` are gone; `ParseRequest` and `ParseHeaderBlock` lost their config parameter. No program or case set them, and they contradicted the point of the parser: every byte follows the RFC 9112 grammar. `PreserveHeaderCase`, accepted and ignored since the port, is gone too, and so is the parse error `h1peStatus` (`peStatus`), which only a response parser could produce. The expected-value tests keep the cases that ran with the strict configuration (the parser corpus is unchanged; 5 449 role cases that only exercised the options are gone).
- **Error kinds and outcomes that nothing produced are gone**: `hekCanceled`, `hekChannelClosed`, `hekUnexpectedMessage`, `hukNoUpgrade`, `NewClosed`, `IsCanceled` and `IsClosed` of the error record, and the outcomes `coCanceled` and `coClosed` (so the metric `bearings_connections_closed_total` has no `canceled` and `closed` labels). They were hyper's error taxonomy, kept "for completeness".
- **`cmWithoutShutdown` is gone**, with `TConnParts` and `TConnObserver.OnParts`. The mode handed the socket and the unread bytes back to the observer when the connection ended; it existed for the tests ported from hyper's `without_shutdown()` API, and no program used it. `TH1ConnMode` is `cmPlain` or `cmWithUpgrades`. The conformance cases that only exercised the hand-off are gone (`upgrades` and `http_connect`, whose upgrades `upgrades_new` and `http_connect_new` cover with `with_upgrades`, and the extra case `without_shutdown_parse_error`); the three header-timeout cases that used the mode run in `plain` mode. (A bug of that mode, the automatic 400 dropped when the socket did not take it at once, was found and fixed on the way; the fix went with the mode.)

- **The conformance runner no longer misses an event that arrives while it starts to wait.** `await_event` and `expect_events` checked the event log, gave up its lock and only then waited, so an event the reader thread added in between woke nobody and the step went on only at its timeout (1 s by default). In `extra-cases::disconnect_during_delay` the client then closed after the handler's 300 ms delay, and the case failed with `handler_done` instead of `handler_dropped`: about one run in ten under the Python of the `python/` environment, which is a free-threading build. - **The differential tests against hyper and httparse are replaced by expected-value tests.** `tests/unit/test_golden.sh` (in `make test`) runs the parser, the request head rules and the body decoder over frozen cases and compares each result with `tests/golden`. The values were taken from httparse 1.10.1 and hyper v1.12.0 on 2026-11-04, with the two rules above applied after every difference was checked. `UPDATE=1` lists the lines that change and rewrites the files. The cases are fewer than the differential tests generated (role 41 000 instead of 200 000, decode 10 000 instead of 100 000, 50 000 random parser inputs instead of 200 000), so that the files stay at 2.8 MB.

The conformance gate already checked the cases in assertion mode; it no longer runs the reference server for a diff report, and `gate_worker.sh` no longer runs the worker probe against it. hyper stays only in `bench/`, for the benchmark.
- **The conformance case runner is a Pascal program** (`conformance/runner/`, built by `conformance/runner/build.sh`), and so is the dumb server; the Cargo workspace is gone, and `make test-full` no longer needs cargo. The runner uses no Bearings unit. It reads JSON with fpjson; a `\u0000` escape is refused (fpjson drops it: a NUL byte is a `{"hex": "00"}` part). Before the Rust runner was removed, the Pascal one gave the same outcome, and the same failing step for failing cases, on every case against `beconf` (inline, worker executor, four loops) and against the dumb server.
- **The cases have no regular expressions.** The 23 `regex` / `not_regex` assertions (Rust's `regex::bytes` dialect) were replaced by byte assertions that state what each one checked, and by a new `utf8` assertion (11 of them checked that a response is valid UTF-8). `runner selftest` checks the runner's own parts; each rewritten assertion was checked to fail when its expected value is wrong. The `diff` mode (two servers' transcripts) and `$regex` event patterns are gone.
- The split fuzz corpus no longer adds httparse's test inputs when their source is in the cargo registry, so it is the same on every machine.

# 0.4.1

- **Raising the descriptor limit is now a choice: `TServerConfig.RaiseFdLimit`.** 0.4.0 raised the process's soft limit on open file descriptors to the hard limit at every `Start`. That was wrong for a library: the limit belongs to the whole process, `select()` cannot take a descriptor >= 1024 (the reason systemd leaves the soft limit there), and child processes inherit the raised limit. `ProductionServerConfig` and `BenchmarkServerConfig` set the option; `Default(TServerConfig)` does not.
- **C API and Python**: `bearings_config_t` has `raise_fd_limit` after `metrics`, and `Server` takes `raise_fd_limit=False`; both are off by default because the host program owns the process. Programs built against the 0.4.0 header must be rebuilt.
- **test_server**: the load client of the stop-under-load tests retries a connect that ends in `ECONNRESET`, the result Linux gives when the closing listener resets a connection before `connect` returns; the test failed once in CI for that.

# 0.4.0

The access log was reworked. Its lines have the keys of structlog's lines, so a log collector reads the server's lines and a Python application's the same way.

- **The JSON lines use structlog's keys**: `timestamp` (RFC 3339 UTC, microseconds), `level`, `logger` (`"bearings"`), `event` (the method and the path, `"GET /x"`), `request_id`, `method`, `path`, `query`, `status`, `size`, `duration`, `client`, `user_agent`, `referer`. They replace the OpenTelemetry names (`time`, `client.address`, `http.request.method`, `url.path`, `url.query`, `http.response.status_code`, `http.response.body.size`, `http.server.request.duration`, `http.response.header.x-request-id`, `user_agent.original`). `network.protocol.version` is gone: the server only speaks HTTP/1.x.
- **The JSON lines have the response's X-Request-ID**, as `request_id`, when the response has the header. An application or a proxy behind the server sets it to find the request in its own logs; the key is absent when the header is.
- **Each line has a level, and a minimum level filters the log.** A line has the level of its status: `error` for a 4xx or a 5xx, `info` for the others. `AccessLog.MinLevel` (`access_log_level` in the C API and in Python) drops the lines below it, so `warning` or `error` keeps only the requests that failed. The default keeps every line.
- **A console format replaces the Combined Log Format.** `alfConsole` (`"console"` in Python, `BEARINGS_ACCESS_LOG_CONSOLE` in C) writes one short line for people: `02:25:45.698455Z [info]  200 GET /projects/1  (153.186ms; 15.69 KB)`. `Colors` (`access_log_colors`) gives the level structlog's ANSI color; Python turns colors on by default when stdout is a terminal. `alfCombined`, `"combined"` and `BEARINGS_ACCESS_LOG_COMBINED` are gone.
- **User-Agent and Referer are written only when asked.** `UserAgent` and the new `Referer` (`access_log_user_agent`, `access_log_referer`) add the headers to the lines in both formats; both are off by default. The Combined format wrote them always.
- **C API**: `bearings_config_t` has four new fields after `access_log`: `access_log_level`, `access_log_user_agent`, `access_log_referer` and `access_log_colors`. Programs built against the old header must be rebuilt.
- **`Start` raises the soft limit on open file descriptors to the hard limit** (`RaiseFdLimit` in `bearings.rt.net`). Every connection is a descriptor, and the soft limit is often 1024 where the hard limit is 524288 (systemd's defaults); a server that reached it could accept nothing more and paused its listeners. Only `LimitNOFILE=` or `ulimit -Hn` bounds the connections now.
- **Pascal API**: `TAccessLogConfig` has `Referer`, `Colors` and `MinLevel: TLogLevel`. `bearings.server.accesslog` adds `TLogLevel`, `LOG_LEVEL_NAMES` and `AccessLevel`; `TAccessLog.Create` and `FormatAccessLine` take `Colors` where they took `UserAgent`; `TAccessRecord` lost `Version`.
